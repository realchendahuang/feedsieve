# Clef 接入与评测（2026-10-22）

> 决策模型：`@cf/cloudflare/clef-flash`（Workers AI）。评测脚本：`scripts/eval-clef.mjs`；测试集：`scripts/eval-clef.cases.jsonl`；本轮原始结果：`/tmp/eval/clef-run/`。
> 一句话：**文本意图判定可用（F1 92.1%），AI 生成判定不可用（AUC 0.79 但绝对概率全在 0.16 以下），账号维度是补短板的唯一现实路径。**

## 0. 结论

| 项 | 实测值 | 说明 |
| --- | --- | --- |
| clef-flash 垃圾判定 | P 97.2% / R 87.5% / F1 92.1% / FPR 5.0% | 60 条自造对抗集，阈值 0.5 |
| L1 规则同集 | P 100% / R 32.5% / F1 49.1% | 默认启发式，不含社区名单/指纹 |
| 规则 ∪ clef | P 97.3% / R 90.0% / F1 93.5% | 剩余 4 条漏判：3 条 AI 拟态 + 1 条弱引流 |
| 延迟（并发 8） | 均值 551ms / p50 381ms / p95 1011ms / max 3686ms | 60 次调用总墙钟 5.4s |
| token | 均值 217.1 / 次（205–242） | 状态 + 一个 `noul` 问题 |
| 单次成本 | $0.00000825 | $0.038/M input，output 不计费 |
| AI 生成探测 | 正样本 0.090、负样本 0.054，AUC 0.790 | 阈值 0.5 时召回 0；阈值 0.11 时只捞回 3/10 且不误伤 |
| 账号元数据探针（合成 8 条） | 批量号 0.617–0.808，真人 0.348–0.576 | 排序 AUC 0.867，概率区间重叠 |

三条可执行判断：

1. **clef 值钱的地方是“意图”，不是“文风”**。它能在没有关键词的情况下认出「主页有惊喜 哥哥来嘛」「空投白名单 私信领取」「评论区扣 1」这类变体，补上 L1 规则 27 条漏判中的 23 条。
2. **不要问它“是不是 AI 写的”**。本集 10 条 AI 拟态文案只给出 0.041–0.157，20 条真人 0.024–0.108；调到能抓 90% AI 的阈值 0.05 时，45% 的真人会被一起标。
3. **账号维度要独立成一路，不要塞进同一个概率**。实测把“像个营销号”的元数据拼进状态后，3 条 AI 漏判全部升到 0.74–0.83，但同一段真人吐槽配同样的元数据也被拉到 0.74–0.77——两路必须分开打分，再在决策层融合。

## 1. 评测设置

### 1.1 测试集

上一轮（`docs/11-规则vs决策模型评测-2026-10-22.md`）用的 120 条 `/tmp/eval/cases.jsonl` 已被清理，本轮自造 60 条（`scripts/eval-clef.cases.jsonl`），7 类，40 spam / 20 ham：

| 类别 | 条数 | 标签 | 设计意图 |
| --- | ---: | --- | --- |
| 黄推 | 10 | spam | 露骨/隐语/emoji/乱码号，含 5 条规则能抓的硬样本 |
| 币圈 | 10 | spam | 假抽奖、带单、空投、t.me 引流 |
| 私域引流 | 10 | spam | 公众号/微信/VX/扫码/评论区扣 1 |
| AI 拟态 | 10 | spam | 大模型口吻的软性引流，**`ai: true`** |
| 真人正常 | 10 | ham | 技术、生活、新闻、求推荐 |
| 真人带脏话 | 5 | ham | 情绪发泄，脏话不是垃圾信号 |
| 边界嘲讽 | 5 | ham | 讽刺平台/算法，容易误伤 |

样本全部为自造，不是真实流量；`n=40` 时召回率的 95% Wilson 区间约 **74%–95%**，结论只用于方向判断和阈值初筛。

### 1.2 判定口径

- clef：`spam` 问题 `noul ≥ 0.5` 判垃圾（另给 0.30–0.80 扫描）。
- 规则：`detect(input)` 返回非 `null`，默认启发式，不注入社区名单、指纹、域名（避免用同一份语料“背答案”）。
- 并集：两者任一命中。
- 失败样本从指标中剔除并单独计数（本轮 0 失败）。

### 1.3 脚本

```bash
# 主评测 + 规则同集对比
node scripts/eval-clef.mjs --cases scripts/eval-clef.cases.jsonl \
  --concurrency 8 --out /tmp/eval/clef-run

# 追加 AI 生成探测（只跑 ai 字段非 null 的样本）
node scripts/eval-clef.mjs --cases scripts/eval-clef.cases.jsonl --probe ai

# 冒烟 / 只看规则
node scripts/eval-clef.mjs --limit 5
node scripts/eval-clef.mjs --dry-run
```

能力：

- jsonl 进，`results.json` + `summary.md` 出；逐条打印 `spam` 概率、延迟、token。
- 8 路固定并发池，单条失败重试 3 次（只对 429/5xx/网络错误重试，4xx 直接失败，避免烧额度）。
- 指标：P/R/F1/准确率/FPR、分类别、阈值扫描、最佳阈值、延迟 p50/p95、token 与费用。
- 规则层直接 import `packages/detector/src/index.ts`（用 `module.registerHooks` 补 `.ts` 扩展名），不复制、不改源码。
- `images` 字段可选，可直接跑 vision 样本。

### 1.4 接口实测形状（与交接描述有出入）

```json
{
  "model": "clef-flash",
  "state": "账号：@xxx\n昵称：…\n简介：…\n最近推文：…",
  "images": ["data:image/png;base64,..."],
  "questions": {
    "spam": {
      "type": "noul",
      "instructions": "判断该账号/该条内容是否属于垃圾推广…",
      "criteria": {}
    }
  }
}
```

返回：

```json
{ "result": { "answers": { "spam": { "type": "noul", "noul": 0.9196 } },
              "usage": { "input_tokens": 166, "output_tokens": 0 } } }
```

三个坑（都实测过）：

1. **`noul.criteria` 必须是对象，不能是字符串**。传文本会报 `questions.spam.noul.criteria: Input should be a valid dictionary`（code 3030）。判据全部写进 `instructions`，`criteria` 给 `{}`。
2. **`images` 只接受字符串数组**（data URI 或 URL），对象数组报 `image object has invalid fields`。图片 token 近似 `像素数 / 1024`，小图有约 64 token 的下限。
3. **问题定义本身计 token**。同一段状态，1 个短问题 152 token，完整 `spam` 问题 217 token，再叠加 `choice` + `score` 两个问题 328 token。多问一句不是免费。

`choice` / `score` 的实际形状（备查）：

- `choice.criteria` 是 `{标签: 描述}` 映射，**至少 2 项**；返回 `choice` + `probabilities` + `confidence`。
- `score.criteria` 是字符串图例数组；返回 `score`（0–1）+ `legend` + `probabilities`，本质是按图例分箱后的归一化值，不是任意连续量。

## 2. 结果

### 2.1 总体

| 判定器 | TP | FP | FN | TN | P | R | F1 | FPR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| clef-flash | 35 | 1 | 5 | 19 | 97.2% | 87.5% | **92.1%** | 5.0% |
| L1 规则 | 13 | 0 | 27 | 20 | 100% | 32.5% | **49.1%** | 0% |

规则单独的精确率是 100%，但只覆盖硬模板（`templated-text` 7 条、`porn-bait-zh` 3 条、`default-name-digits` / `word-salad` / `contact-number-bait` 各 1 条）。

读法：

- **币圈是 clef 的舒适区**，10/10 全中，平均分 0.92，连 `$PEPE2 … join t.me` 这种没有关键词的也认。
- **AI 拟态是唯一明显短板**：平均分 0.56，3 条掉到 0.03–0.11，而且这 3 条恰恰是“没有明确 CTA、只把资料放主页”的那批。
- **真人带脏话完全没有误伤**（0.021–0.036），这条很重要：脏话不等于垃圾。
- **边界嘲讽有 1 条误判**（`sa-05` 0.719），另外 `sa-02`（Pornhub 分站）0.409，说明模型对反讽不敏感，对“提及色情词”偏敏感。

### 2.3 阈值

| ---: | ---: | ---: | ---: | ---: |
| 0.30 | 94.7% | 90.0% | 92.3% | 10.0% |

最佳阈值 0.10（P 95% / R 95% / F1 95%），但这是在同集上调出来的，偏乐观；0.50 与它只差 2.9pp，**建议先固定 0.50**，等真实分布再校准。0.30 以下误伤明显上升，不要用。

### 2.4 延迟与 token

- 并发 8：均值 551ms，p50 381ms，p95 1011ms，max 3686ms；60 次总墙钟 5.4s（约 11 次/秒）。
- 串行冒烟时单次 0.88–2.82s，与交接的 1.0–1.1s 一致；并发下更快，疑似同前缀 prompt 命中边缘缓存，**不要把它当 SLA**。
- token 205–242，均值 217；问题定义约 140 token，状态按长度另计（中文约 1 token/字）。
- 本轮 60 次共 13,026 token，$0.0005。

### 2.5 错误分析

| 类型 | 样本 | 分数 | 原因 |
| --- | --- | ---: | --- |
| FP | `sa-05`「你管这叫『为你推荐』？我谢谢你啊。」 | 0.719 | 纯反讽，模型读成“推广口吻” |
| 临界 | `sa-02`「建议直接把 X 改名 Pornhub 分站」 | 0.409 | 提及色情平台，但语境是骂算法 |
| FN | `ai-03` 早起作息表放主页 | 0.026 | 无 CTA、无营销词，像正常生活贴 |
| FN | `ai-08` 书单放主页 | 0.070 | 同上 |
| FN | `ai-10` 第 200 天，资料放主页 | 0.106 | 弱 CTA |
| FN | `hb-02`「我福不黑，不信你看」 | 0.116 | 中文隐语，模型没接住；规则命中 |
| FN | `sy-10`「看我主页第一条」 | 0.389 | 引流强度足够低，阈值下未过线 |

规则侧 27 条漏判集中在：私域引流 8 条、AI 拟态 10 条、币圈 4 条（`空投白名单`、`$PEPE2`、`加V`、`跟着老师`）、黄推 5 条（`同城上门`、`主页有惊喜`、`约啪` 等）。这些正是 clef 补上的部分。

### 2.6 判断

- clef 的强项是**跨语言、去关键词的意图识别**，适合做 L1 之后的第二层。
- 它的输出概率是**可用的置信度**（真人 0.02–0.10、典型垃圾 0.81–0.95），不像 AI 检测那样整体压在低分区。
- 一次误判是反讽，说明纯文本层要留“不自动拉黑、只黄框”的产品边界——与现有 `可见优先，拉黑唯一` 一致。

## 3. 短板验证：AI 生成不可判

### 3.1 实验

只给正文与简介（剥掉 handle、昵称），问一个问题：

> 判断这段文本是否由大语言模型（AI）自动生成或大幅改写。真人随手写的口语、错别字、网络梗都应判为非 AI。

30 条：10 条 AI 拟态（正）+ 20 条真人（负：正常 10、脏话 5、嘲讽 5）。

### 3.2 结果

| 组 | n | 均值 | 范围 |
| --- | ---: | ---: | --- |
| AI 拟态 | 10 | 0.090 | 0.041–0.157 |
| 真人 | 20 | 0.054 | 0.024–0.108 |

AUC 0.790（排序上有弱信号），但**绝对概率全部低于 0.16**：

| 阈值 | P | R | F1 | 被判为 AI 的真人 |
| ---: | ---: | ---: | ---: | ---: |
| 0.50（生产默认） | — | 0% | 0% | 0/20 |
| 0.11 | 100% | 30% | 46% | 0/20 |
| 0.10 | 80% | 40% | 53% | 1/20 |
| 0.05 | 50% | 90% | 64% | **9/20** |

### 3.3 解读

- 陈哥的结论“决策模型不是 AI 文本检测器”在本集**复现**：方向一致，绝对分甚至更低（本集文案更口语、更短）。
- AUC 0.79 不代表可用：要在不误伤真人的前提下拿到 30% 召回，只能把阈值压到 0.11，而这个阈值换一批真实数据就会漂移。
- 根因不是提示词没写好，而是模型训练目标是“给定状态回答业务问题”，不是“作者归属鉴定”。继续调 prompt 的边际收益很低。

### 3.4 对产品的含义

**不要**把“AI 味”做成一个独立规则或一个用户可见的标签。它能提供的只是“这条文案可疑”的弱先验，必须由账号行为证据来坐实。

## 4. 不依赖单条文本的方案

### 4.1 原则

```text
文本 → 判“这次传播的意图”（clef 擅长）
账号 → 判“这个主体的运营形态”（确定性特征，本地算）
决策层 → 两路独立证据融合，账号证据只升级处置等级，不单独定罪
```

理由来自实测：把账号元数据拼进 clef 的同一个状态后，3 条 AI 漏判全部升到 0.735–0.830，但真人吐槽配上同样元数据也被拉到 0.742–0.771。**同一个概率里混了两种证据，就无法解释、也无法校准。**

### 4.2 特征清单

| # | 特征 | 数据来源 | 插件侧获取方式与成本 | 更新 | 信号 | 风险 |
| --- | --- | --- | --- | --- | --- | --- |
| A1 | 账号年龄 | `UserByScreenName` 的 `created_at`、资料页 DOM | 仅在灰区账号上抓一次 profile，缓存 30 天；1 次网络请求 | 30 天 | 强（新号 <30 天） | 新真人被连坐；需与 A2 组合 |
| A2 | 发帖节奏：间隔中位数、CV、突发度 | 时间线里同账号多条 `time[datetime]` | 本地 IndexedDB 环形缓冲，零网络，<1ms | 实时 | 强（CV<0.3 + 中位间隔 <10min） | 直播/新闻账号也高频 |
| A3 | 跨账号文案 SimHash 重合 | 已有 `simhash.ts`（v1） | 本地存 64-bit 前缀桶，O(1) 查重；或 Worker KV 全局查 | 实时 | 强（同模板 ≥3 账号） | 引用/转发会被误算，需去重 repost |
| A4 | 粉丝/关注比 | 资料页 DOM、悬停卡 | 随 A1 一起抓，边际成本 0 | 30 天 | 中 | 新真人关注多很正常 |
| A5 | 互关率 | Following 列表（已有同步器） | 本地集合求交，零网络 | 天 | 中 | 只对已同步用户有效 |
| A6 | 互动结构：回复/转推/点赞比、回复者去重 | 帖子 DOM 的 aria-label 计数 | 本地累计，零网络 | 实时 | 中（高展示低互动） | 小号本身互动少 |
| A7 | 头像视觉 | `pbs.twimg.com` 头像 URL | 背景页取图 → OffscreenCanvas 缩到 128 → data URI → clef vision | 按账号 7 天 | 中（AI 生成人像/网图/二维码） | 二次元头像在真人里极常见，不能单独用 |
| A8 | 头像感知哈希聚类 | 本地 dHash | 32×32 灰度算 64-bit dHash，前缀桶聚类，零网络 | 实时 | 中（同批号同头像） | 默认头像需排除 |
| A9 | 自我重复率 | 同账号历史文本 | 本地 simhash 集合，零网络 | 实时 | 中（复制自己旧帖） | 活动/置顶重复 |
| A10 | 发帖时间分布（UTC 小时直方图） | `time[datetime]` | 本地直方图，零网络 | 实时 | 弱 | 跨时区真人 |
| A11 | 资料完整度（bio/banner/位置/认证） | 资料页 DOM | 随 A1，边际 0 | 30 天 | 弱 | 大量真人也不填 |
| A12 | 外链域名/短链共享 | `links`（已有） | 本地集合，零网络 | 实时 | 中 | 正常推广也会共享域名 |

**成本原则**：A2/A3/A6/A8/A9/A10/A12 全部本地零网络；只有 A1/A4/A7/A11 需要一次资料或图片抓取，且只在“灰区账号”上触发。按每账号 30 天一次估算，单账号额外成本约 1 次 profile 请求 + 1 次头像请求。

### 4.3 仓库里已经有的零件

- `packages/detector/src/simhash.ts`：v0/v1 双版本 SimHash，已有汉明距离阈值，可直接做 A3/A9。
- `packages/detector/src/fingerprint.ts`：精确模板指纹，社区快照已在用。
- `apps/extension/src/lib/platform/xhr-bridge-guard.ts`：已经在解析 timeline 内嵌的 `following` 关系与账号 JSON，可扩展取 `created_at`、`followers_count`。
- `apps/extension/src/lib/detection/detection-log.ts`：本地判定日志，可作为账号特征的回放数据源。
- 社区快照 `campaign_size` / 指纹集合：天然的跨账号聚类结果，A3 可先复用，再补本地实时计算。

| `ai-08` | 0.070 | **0.830** | — |
| `ai-10` | 0.106 | **0.735** | — |
| `hm-01` 真人技术贴 | 0.014 | **0.771** | 0.028 |
| `hm-02` 真人生活贴 | 0.017 | **0.742** | 0.020 |

两个结论：

1. 账号特征确实能把 3 条 AI 漏判全部捞回来（0.735–0.830）。
2. 它也会把真人文本一起拉高（0.74–0.77），**说明元数据在 prompt 里权重过高**。生产上要么两路分开，要么把账号特征做成确定性分，绝不能让一个混合概率直接触发标注。

### 4.5 预期提升（场景估算，不是实测）

基线（规则 ∪ clef）：TP 36 / FP 1 / FN 4 / TN 19，F1 93.5%。剩余 4 条 FN 中 3 条是 AI 拟态、1 条是弱引流。假设账号路由只作用于灰区，按下表估算：

| 捞回 FN | 新增 FP=0 | 新增 FP=1 | 新增 FP=2 |
| ---: | --- | --- | --- |
| 1 | P 97.4 / R 92.5 / **F1 94.9** | 94.9 / 92.5 / 93.7 | 92.5 / 92.5 / 92.5 |
| 2 | 97.4 / 95.0 / **96.2** | 95.0 / 95.0 / 95.0 | 92.7 / 95.0 / 93.8 |
| 3 | 97.5 / 97.5 / **97.5** | 95.1 / 97.5 / 96.3 | 92.9 / 97.5 / 95.1 |
| 4 | 97.6 / 100 / **98.8** | 95.2 / 100 / 97.6 | 93.0 / 100 / 96.4 |

按合成探针的表现（3 条 AI 漏判全部捞回、真人 0 误伤），**乐观上界 F1 97.5%**；若账号路由每捞回 1 条就多 1 条误伤，收益基本被吃掉（96.3%）。所以账号特征的验收标准不是“能抓多少”，而是**每千次判定新增误伤 ≤1**。

必须实测才能定论的部分：

- A2（节奏）与 A3（跨账号重合）在真实垃圾网络上的单特征 AUC；
- 新真人（注册 <30 天）被 A1 连坐的比例；
- A7 头像视觉对 AI 拟态账号的实际增益（本轮没有真实头像样本）。

### 4.6 视觉输入

格式与成本（实测，128px 以内性价比最高）：

| 输入 | token | 相对纯文本 | 延迟（3 次范围） |
| --- | ---: | ---: | --- |
| 纯文本 | 152 | — | 351–888ms |
| 64×64 | 219 | +67 | 435–511ms |
| 128×128 | 219 | +67 | 431–717ms |
| 256×256 | 219 | +67 | 842–1509ms |
| 512×512 | 411 | +259 | 767–1477ms |

结论：

- **头像统一缩到 128×128**（WebP/JPEG q0.8，base64 约 6–10KB），成本 +67 token，延迟与纯文本同档；256px 起延迟上到 0.8–1.5s，512px 的 token 涨到近 4 倍。
- 图片 token ≈ `像素数 / 1024`，有 ~64 token 下限；1024×1024 实测 1179 token、延迟 1.1–2.5s，是 128px 的 17 倍 token，不值得。
- 用法：只在“文本灰区 + 账号特征可疑”时，对头像问一个 `choice` 问题（真人照片 / AI 生成人像 / 二次元插画 / 二维码或文字截图 / 默认头像），作为账号路由的一条证据。
- 风险：二次元头像在真人用户中占比不低；**头像永远不能单独触发标注**。另外取头像要跨域读图（`pbs.twimg.com`），需在 background 用 `fetch` + OffscreenCanvas，避免 canvas 污染。
- 隐私：上传头像属于把用户可见内容发给第三方，必须 opt-in，并在 `PRIVACY.md` 写清。

## 5. 接入架构

### 5.1 总览

```text
X 页面
  └─ content script
       ├─ L1 规则（detector，本地，始终先跑）
       ├─ 账号特征（IndexedDB 环形缓冲：节奏/互动/自我重复）
       ├─ 判定缓存（IndexedDB：simhash → verdict）
       └─ 灰区？ ── 否 ─→ 直接用 L1 结果渲染
                   └─ 是 ─→ background service worker
                              └─ POST /v1/verdict（异步，不阻塞渲染）
                                   │
                              Worker: feedsieve-ai-gateway
                                ├─ 鉴权（install token + HMAC）
                                ├─ 限流/预算（DO 令牌桶 + 日预算）
                                ├─ 缓存（KV：simhash → verdict，7d）
                                ├─ 账号记忆（DO：handle hash → 特征与历史）
                                └─ env.AI.run('@cf/cloudflare/clef-flash')
                                     │
                                  Workers AI
```

建议新建独立 Worker `apps/ai-gateway`，而不是继续堆在 `community-api`：后者承载官网 SSR、D1、R2、公开缓存，AI 代理需要独立的限流、预算与故障隔离；同账号部署，通过 service binding 复用社区快照。若想省事，也可以先在 `community-api` 加一条 `/v1/verdict` 路由，但要把 `cache: enabled` 的共享缓存显式 `no-store`。

### 5.2 插件侧

1. **L1 永远先跑**，黄框立即渲染，不等网络。
2. 只在灰区（规则未命中、且账号风险分未到“确定干净”）发起 clef 判定；判定返回后**补丁式**更新标注，绝不因为等待而延迟渲染。
3. 每个账号 24 小时内最多一次文本判定 + 一次头像判定；文本层按 simhash 去重，同模板直接复用。
4. 账号特征在 content script 本地算（A2/A3/A6/A8/A9/A10/A12），只把**结论**（风险分 + 证据名）发给 Worker，不上传原始行为序列。
5. 超时 2.5s；连续 5 次失败或 429 触发熔断 10 分钟，期间只用 L1 + 本地缓存。
6. 用户手动 unblock/标记“误报”作为负反馈，进入本地校准队列（可选上报，默认关闭）。

### 5.3 Worker 代理

职责与顺序：

1. 校验 install token（由现有账号体系签发，HMAC/Ed25519 签名，带过期）。
2. 规范化文本（NFKC、去零宽、URL 参数剥离、手机号/邮箱脱敏），算 simhash。
3. 查 KV 缓存：`v1:clef-flash:zh-spam-2026-10-22:<simhash>`，命中直接返回（`cached: true`）。
4. 查账号记忆 DO：取最近判定、节奏特征、账号年龄（若已抓取）。
5. 组装状态：**只放文本相关字段**；账号特征不拼进 clef 的 `state`（见 4.4），而是随响应一起回给插件，由本地融合。
6. 调 `env.AI.run('@cf/cloudflare/clef-flash', body)`，超时 2.5s，失败重试 1 次（仅 429/5xx）。
7. 按置信度写缓存：`score < 0.2` 或 `> 0.8` 缓存 7 天；中间带缓存 1 天（防对抗样本污染）；带 `prompt_version`，提示词一改全量失效。
8. 记账：`input_tokens`、延迟、模型版本写入 Analytics Engine，不落原文。

契约示例：

```json
// POST /v1/verdict
{ "text": "…", "lang": "zh", "simhash": "3f2a…", "account": { "ageDays": 12, "cadenceCv": 0.2 },
  "want": ["spam"], "images": [] }

// 200
{ "spam": 0.83, "cached": false, "model": "clef-flash@2026-10",
  "promptVersion": "zh-spam-2026-10-22", "tokens": 217, "latencyMs": 410 }
```

### 5.4 缓存与账号记忆

- **文本缓存**：simhash 做键，天然吸收换空格、全角半角、表情变体；同一 campaign 几千条只花一次钱。
- **账号记忆**：Durable Object `acct:{blake3(handle)}`，存 64 条环形缓冲（时间戳、simhash、判定）、派生特征、最近判定时间；TTL 30 天。A2/A3/A9 在这里做全局聚合，插件侧只做本地回退。
- **负缓存**：4xx 请求体错误不缓存，避免坏请求反复打；超时结果不缓存。
- **失效**：模型或提示词版本变更 → key 前缀变更，老缓存自然淘汰。

### 5.5 离线降级

| 场景 | 行为 |
| --- | --- |
| 无网络 | 只用 L1 + IndexedDB 里的历史判定；不排队、不重试 |
| 超配额 / 402 / 429 | 熔断 10 分钟，返回 `fallback: "local"`，界面不提示错误 |
| 超时 2.5s | 丢弃本次结果，保留 L1 标注；下次滚动再试 |
| 5xx | 重试 1 次后放弃，计入熔断计数 |
| 模型下线 / 改版 | Worker 侧版本钉住 + 远端 kill switch（复用现有 `/v1/kill-switch`） |
| 隐私模式 | 完全禁用云端，只跑 L1 与本地缓存 |

产品语义：**降级只影响“多认出多少”，不影响“已经认出的”**；任何情况下都不隐藏内容、不阻塞滚动。

### 5.6 隐私与合规

- 默认只在灰区发送**脱敏后的文本**；handle 不上传（或只传 HMAC）。
- 头像上传必须单独 opt-in，且只传 128px 缩略图。
- 不回传原文、不落日志；只记 simhash、分数、模型版本、耗时。
- `PRIVACY.md` / `DISCLAIMER.md` 增补“内容会发送至 Cloudflare Workers AI 做判定”，并给出关闭开关。
- 企业/教育场景可配置“只用本地 L1”。

### 5.7 灰度与监控

影子模式先跑 2 周：只记录 clef 分数与规则结果，不改变界面。监控：

- 每千次判定的误报数（以用户 unblock / 手动豁免为准）；
- 缓存命中率、p95 延迟、每日 token 与费用；
- 各类别分数分布漂移（模型或流量变化）；
- 规则与 clef 的一致率（突然下降 = 上游变了）。

### 6.4 优化

- **simhash 缓存**是最大杠杆：同一 campaign 的几千条变体只算一次。真实流量里的重复率需实测（本集无重复模板，无法给出比例）。
- **账号级缓存 24h**：一个账号一天只判一次文本 + 一次头像，成本从“按帖”降到“按账号”。
- **问题数量**：每多一个问题约 +60–90 token（实测 3 个问题比 1 个多 176 token）。只问 1 个 `spam`，分类用离线映射规则推，不要多问。
- **头像 128px**：512px 比 128px 贵 4 倍 token，判定增益需实测，先按 128 上线。

### 6.5 备注

- **与 docs/11 的 DeepSeek 方案同口径对比**：DeepSeek 非思考 ¥0.45/千条、思考 ¥1.43–2.87/千条，p50 2.62–2.97s；clef 实测 $0.0083/千条（约 ¥0.059）、p50 381ms。按 1 USD≈7.1 CNY 粗算，clef 比 DeepSeek 非思考便宜约 7.6 倍、快约 7 倍；但 DeepSeek 那轮用的是 1,150 token 的 few-shot prompt，两者输入长度不同，不能直接归因于模型能力。
- Workers AI 免费额度按 Neurons 计，换算以控制台账单为准；本文只算 token 费。
- Workers 请求费、KV/DO 读写费未计入，量级远小于 token 费。
- 以上不含重试与影子模式流量；影子模式按全量跑一遍，上线前预算翻倍。
