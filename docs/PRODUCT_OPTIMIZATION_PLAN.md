# FeedSieve 优化文档落地与分阶段实施计划

> 版本：2026-09-06  
> 状态：实施中  
> 主原则：安装即用、低打扰、高准确率、高效率、社区共建自动完成。

## 总体目标与默认行为

FeedSieve 的首要目标是让用户安装后立即获得可用的 X 时间线清理能力。用户不需要完成首次向导，也不需要在每次识别、拉黑或社区贡献时重复做决定。

默认行为固定为：

- 检测默认开启。
- 社区名单默认开启。
- 自动社区贡献默认开启。
- 安装后直接使用，不显示 onboarding，不要求选择分类。
- 默认继续使用较窄的黄推 / 成人引流词库，降低误判；其他能力随词库更新自动获得。
- 设置中提供“仅本地运行”开关，默认关闭。打开后停止社区贡献，但本地识别、标注和拉黑继续可用。
- 管理员保存名单或词库后立即生效，不增加强制发布步骤。
- 保留“用户确认后拉黑”的安全边界。系统负责自动识别、标注、排队、重试和上报，用户只处理需要判断的事项。

## 当前审计结论

当前本地质量基线已经通过：

```bash
pnpm typecheck
pnpm test -- --reporter=dot
pnpm build:extension
```

现有检查结果为 7 个 workspace 类型检查通过、25 个测试文件共 200 个测试通过、扩展构建成功。

需要优先处理的结构性问题：

- X 会复用时间线 article 节点，现有只记录元素是否扫描过的逻辑可能保留过期识别结果，也可能漏掉异步到达的 bio 证据。
- MutationObserver 触发后会对整个文档重新查询，长时间线和高频动态更新下会增加主线程压力。
- 页面批量拉黑仍然直接循环执行，不能像社区批量一样在 popup 关闭、页面刷新或浏览器重启后可靠恢复。
- popup 会向所有 X 标签页尝试发送消息，存在操作发往错误标签页的风险。
- X 时间线实测中每条可见推文都出现长文本手动操作，动作栏空间被明显挤压。
- 社区名单当前同步周期为 6 小时，词库为 15 分钟，界面和注释存在周期描述漂移；社区同步还依赖 X 页面或启动事件，没有稳定的定时后台入口。
- `createRepetitionTracker` 已存在于 Detector，但没有接入扩展扫描链路，路线图与实际策略不一致。
- 社区报告的额度检查存在并发竞态；报告、抢救和撤回请求还会同步生成快照，吞吐和响应时间会随数据量增长。
- 管理端已经采用保存即发布，但错误页可能把 HTML 解析异常直接显示给管理员，发布状态、版本状态和失败重试信息也不够清楚。

## 目标架构

### 扩展前台与 content script

将当前 content script 拆为四个职责：

1. `ArticleReader`：提取作者、正文、简介、链接、帖子 ID 和 X 用户 ID。
2. `ScanScheduler`：收集变化节点，控制可见区域扫描和空闲时间分片。
3. `DecorationController`：负责黄框、理由徽章、紧凑操作按钮和隐藏效果。
4. `ActionController`：负责拉黑、撤销、白名单、抢救、社区贡献和错误恢复。

扫描状态从 `WeakSet<Element>` 改为记录文章身份、作者、正文、简介、链接、内容指纹和结果版本的 `WeakMap<Element, ArticleScanSnapshot>`。X 复用 article 节点或 bio 异步返回时，只有相关节点失效并重新检测。

页面批量、社区批量和手动批量统一写入持久化 `BlockJob` 队列。每个任务绑定具体 X 标签页、账号上下文、handle、`xUserId`、来源、证据、贡献策略、重试次数和错误状态。

### 本地存储

blocked、allowlist、following、持久化队列和待同步贡献逐步迁移到 IndexedDB，以 handle、`xUserId` 和账号身份建立索引。迁移必须保留旧 storage 数据的兼容读取和失败回退。

### 后台同步

使用 `browser.alarms` 执行社区名单和词库同步。社区名单维持 6 小时 TTL，词库维持 15 分钟 TTL。安装、更新、浏览器启动和定时同步共用同一套同步函数，并使用指数退避和随机抖动。

同步状态必须区分内置兜底、远程成功、继续使用上次版本和同步失败，并向 popup 提供最后成功时间、版本和待重试状态。

### Detector 策略

保留 allowlist、following、blocked 的最高优先级保护，并维持社区最终名单、内置名单、账号特征、内容特征和本地关键词的分层结构。

`Detection` 增加结构化证据、置信区间、规则版本和内容版本。社区名单继续由服务端独立票数和误标票数决定；本地关键词只生成需要用户确认的标注，不直接改变社区名单。

已有 `createRepetitionTracker` 要么正式接入扫描链路并设置严格阈值、时间窗口和账号关联条件，要么删除死代码和对应路线图承诺。

### 社区 API 与管理端

管理员继续使用保存即生效。保存请求完成校验、数据库写入、审计记录和发布任务登记后立即返回版本和状态；快照生成较慢或失败时由后台完成、重试，并继续保留上一版本。

报告、抢救和撤回使用幂等键；每日额度使用原子更新；批量请求使用批量查询、批量写入和事务；快照生成从用户请求中解耦，并由单一任务协调版本。

管理端保留发布记录和回滚作为高级保障能力，不让普通保存流程经过额外发布页面。错误统一转换为可理解的提示，所有关键请求包含 `request_id`。

## 分阶段实施

### 第一阶段：可靠性和信任边界

- 统一页面批量、社区批量和手动批量的持久化队列。
- 绑定具体 X 标签页和账号上下文。
- 保持自动社区贡献默认开启，增加“仅本地运行”。
- 修复 X 动态复用节点导致的过期识别。
- 使用 `browser.alarms` 执行后台同步。
- 统一同步状态、错误码和任务失败处理。

### 第二阶段：识别准确率和页面性能

- 拆分 content script 的读取、调度、装饰和动作职责。
- 引入脏节点扫描、可见区域扫描、空闲时间分片和内容指纹缓存。
- 接入严格条件下的重复模板检测。
- 将长文本手动按钮改为紧凑图标或悬停 / 聚焦操作。
- 增加规则版本、证据等级和识别结果指标。

### 第三阶段：popup 与本地数据

- 首页围绕待处理、正在执行和已完成组织内容。
- 一键清理当前页面作为主要批量操作。
- 集中展示队列进度、失败数量和待同步贡献。
- blocked、allowlist、following 和队列采用分页或虚拟列表。
- 迁移到 IndexedDB，保留版本化迁移和旧数据回退。
- 拆分 popup 低频视图，减少首次加载包体。
- 完善键盘导航、焦点、减少动画、高对比度和窄屏表现。

### 第四阶段：社区 API 和管理端

- 报告、抢救和撤回加入幂等、原子额度和批量事务。
- 快照生成异步化，加入失败重试和上一版本保护。
- 保存即生效接口统一返回 release、version、effective_at 和 status。
- 增加并发版本号、审计、版本详情和安全回滚。
- 管理端列表增加分页、分类、状态、来源和更新时间。
- 反馈页支持规则、账号、时间和处理状态筛选。
- Dashboard 展示真实的名单、票数、误标率、快照延迟、待处理反馈和失败任务。
- 管理端错误统一处理 JSON、HTML、Access 登录页和网络错误。

## 验收标准

### 扩展

- 安装后无需配置即可开始识别。
- 多个 X 标签页同时打开时不会把操作发到错误页面。
- 关闭 popup 后批量任务仍然执行或可以恢复。
- X 虚拟列表复用节点后，识别结果不会残留或漏更新。
- bio 异步返回后可以补充检测。
- 每条推文不再出现拥挤的长文本按钮。
- 自动贡献默认开启；纯本地模式可以完全阻断社区请求。
- 失败任务具备明确状态，可以重试或暂停。
- 大量时间线变化时不出现明显滚动卡顿。

### 管理端与 API

- 保存账号或词库后立即返回有效状态。
- 快照失败不会让上一版本失效。
- 并发报告不能突破每日额度。
- 重复请求不会重复计票。
- 管理端不显示底层 JSON 解析异常。
- 回滚后客户端能够获取并使用新版本。
- 所有关键操作可以通过 `request_id` 追踪。

### 视觉与可用性

- popup 在 360、420 和系统缩放场景下不溢出。
- X 原生操作栏不被 FeedSieve 操作挤压。
- 所有按钮可通过键盘访问，焦点清楚，触控区域足够。
- 开启减少动画后不执行视图切换动画。
- 空状态、同步失败、队列暂停和权限失效都有紧凑且明确的界面状态。
- 管理端不显示裸错误码或 HTML 解析异常。

## 数据迁移、兼容和失败恢复

- 旧 storage 数据必须在新版本首次启动时完成一次性迁移，并保留旧格式回退读取。
- 队列状态增加 schema 版本，未知字段忽略，未知状态安全降级为暂停。
- API 新增字段保持向后兼容，旧客户端仍可读取公开快照。
- 新快照不可用时继续使用最近一次校验通过的版本或内置兜底。
- 社区贡献网络失败进入待同步队列，不影响本地拉黑。
- X 认证失效、速率限制和接口结构变化暂停队列，避免无意义重试。
- 管理员发布失败时继续保留上一版本，并显示自动重试状态。

## 验证边界

每个阶段继续运行：

```bash
pnpm typecheck
pnpm test -- --reporter=dot
pnpm build:extension
```

本地自动检查通过不等于真实 X 账号、Cloudflare Access、线上快照和人工视觉验收已经完成。发布前必须单独完成本地 X 预览、真实登录态验证、线上 API 烟测、快照回滚验证和人工视觉验收。

## 实施进度

### 2026-09-06 已完成

- 新增统一优化主计划文档。
- 页面批量拉黑接入持久化队列，任务保留来源、理由、证据和社区贡献策略。
- 队列执行使用任务来源和任务级贡献策略，不再把页面批量误当成社区批量。
- popup 只向当前活动的 X 标签页发送清理操作，避免后台标签页误操作。
- 手动漏网账号标记遵守默认自动贡献设置。
- X article 扫描从一次性 `WeakSet` 改为内容版本快照，支持虚拟列表复用和异步 bio 变化后的重检。
- MutationObserver 改为收集脏 article 后再扫描，减少无关节点重复处理。
- 时间线上的清理操作改为短标签，完整含义通过辅助提示提供。
- popup 增加“仅本地运行”开关，默认关闭；队列状态显示来源和本地化状态。
- background 增加社区名单和词库的 `browser.alarms` 定时同步，并在 MV3 manifest 中声明 `alarms` 权限。
- 新增队列持久化、活动标签页安全和默认自动贡献的回归测试。
