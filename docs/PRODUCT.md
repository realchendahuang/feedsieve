# FeedSieve 产品说明

## 一句话

福滤娃 FeedSieve 是一个 X 赛博清洁工：高置信垃圾账号会被黄框提示；插件漏掉的账号，用户可以直接「标记垃圾并拉黑」；关注列表自动成为每个用户自己的本地保护名单。

## 用户问题

用户真正厌烦的通常是重复出现的垃圾账号和垃圾模式：

- 同一批机器人在热门推文下刷相似回复
- 模板化 AI 回复占满评论区
- 色情、灰产和 Telegram 引流
- 复制粘贴营销
- 无意义互动钓鱼
- 币圈老师、广告轰炸

传统“屏蔽类”工具只在本浏览器里隐藏，手机端照旧，也不妨碍垃圾账号继续回复、@ 你、关注你。FeedSieve 直接执行 X 原生 Block：**全端生效 + 阻断互动**。

## MVP 用户路径

1. 用户安装浏览器扩展，打开 X。
2. FeedSieve 识别页面里的推文 / 回复。
3. 高置信社区名单命中被黄框标注，理由写成“3 人标记为诈骗”等普通话。
4. 用户可以拉黑当前页面的高置信候选，也可以启动云端高置信名单清理队列。
5. 用户可在设置中维护自己的关键词，或逐条启停官方按类别提供的完整话术词库；命中仅给黄框与人工确认入口。
6. 插件漏识别时，用户在推文旁或面板输入账号，点「标记垃圾并拉黑」。
7. Block Queue 逐个执行，支持进度、暂停、继续、取消，刷新页面后不会假装仍在运行。
8. 关注列表同步后仅存本机，优先排除关注、个人白名单和已拉黑账号。
9. 误伤：点「放回来」原生 Unblock 恢复。
10. 所有结果进入本地统计，用于「今日战报」。

## 首版必须有

### 判断与标注

- 社区名单分级命中；批量动作只接收 strong + 至少 3 个独立标记 + 0 次抢救
- 用户自定义关键词与可逐条关闭的官方完整话术词库只提示人工确认，不进入批量拉黑、不上传社区；未配置的算法关键词、默认昵称、单次相似文本等弱信号不直接定罪
- 相似内容和可疑域名只在「彻底」档提示复核，不进入批量拉黑
- 每个标注使用用户能理解的理由，不展示 ruleId、指纹、模板等算法术语
- 用户始终可以手动标记漏网账号

### 拉黑

- 待拉黑列表（持久、可增删）
- 一键批量拉黑（队列：进度 / 暂停 / 恢复 / 取消）
- 单账号「标记垃圾并拉黑」
- 云端高置信黑名单一键清理，自动排除关注、白名单和已拉黑账号
- 一键撤销（Unblock）

### 每用户保护名单

- 用户自己的 X 关注列表就是默认保护名单
- 完整同步成功后才原子替换旧版本；失败时旧保护继续有效
- 仅保存在浏览器本地，不作为社区抢救票上传
- 用户仍可显式把某个关注账号标记为垃圾，此时最新的人工判断覆盖关注保护

### UX

标注必须尽量无感：页面除黄框外零改动，滚动不掉帧。

### Statistics

最少统计：

- 标注总数
- 拉黑总数
- 撤销数
- 按类型数量

## 首版不急着做

- 完整第三方 X 客户端
- 云端账号系统
- 社交网络
- 大型后端
- 强依赖付费 AI
- 自动替用户举报账号
- 自动静默拉黑

## AI 策略

AI 不应该成为首层识别器。

合理链路：

`DOM -> 高置信名单 / 弱证据复核 -> 用户确认或手动标记 -> Block`

优点：

- 减少 Token 成本
- 减少延迟
- 减少隐私暴露
- 避免 API 不可用时产品失效

## 今日战报为什么重要

它同时承担三个作用：

1. 用户价值证明：今天到底替你送走了多少垃圾号。
2. 情绪价值：让枯燥统计变成梗。
3. 产品传播：卡片天然适合发到 X。

这不是一个附属功能，应当进入早期 Roadmap。
