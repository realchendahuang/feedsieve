# FeedSieve 产品说明

## 一句话

福滤娃 FeedSieve 是一个 X 赛博清洁工：在你刷 X 的时候认出垃圾账号并黄框标注，你按一下按钮，就把它们批量真拉黑。

## 用户问题

用户真正厌烦的通常是重复出现的垃圾账号和垃圾模式：

- 同一批机器人在热门推文下刷相似回复
- 模板化 AI 回复占满评论区
- 色情、灰产和 Telegram 引流
- 复制粘贴营销
- 无意义互动钓鱼
- 币圈老师、广告轰炸

传统“屏蔽类”工具只在本浏览器里隐藏，手机端照旧，也不妨碍垃圾账号继续回复、@ 你、关注你。FeedSieve 直接执行 X 原生 Block：**全端生效 + 阻断互动**。

## MVP 用户路径

1. 用户安装浏览器扩展，打开 X。
2. FeedSieve 识别页面里的推文 / 回复。
3. 名单命中或启发式命中的垃圾账号被黄框标注（带理由）。
4. 标注账号自动进入「待拉黑列表」（可移除）。
5. 用户按下「一键拉黑 N 个」。
6. Block Queue 通过 X 原生菜单逐个执行 Block。
7. 完成后报告“已送走 N 个，手机端已同步”。
8. 单账号：点「顺手拉黑」直接拉黑。
9. 误伤：点「放回来」原生 Unblock 恢复。
10. 所有结果进入本地统计，用于「今日战报」。

## 首版必须有

### 识别标注

- 社区名单命中（内置 recommended 名单）
- 机器人账号启发式（默认名 + 随机数字）
- 垃圾域名链接
- 模板化文本
- 每个标注带理由

### 拉黑

- 待拉黑列表（持久、可增删）
- 一键批量拉黑（队列：进度 / 暂停 / 恢复 / 取消）
- 单账号顺手拉黑
- 一键撤销（Unblock）

### UX

标注必须尽量无感：页面除黄框外零改动，滚动不掉帧。

### Statistics

最少统计：

- 标注总数
- 拉黑总数
- 撤销数
- 按类型数量

## 首版不急着做

- 完整第三方 X 客户端
- 云端账号系统
- 社交网络
- 大型后端
- 强依赖付费 AI
- 自动替用户举报账号
- 自动静默拉黑

## AI 策略

AI 不应该成为首层识别器。

合理链路：

`DOM -> Feature Extraction -> 名单 / 启发式 -> AI Fallback -> 标注 -> 用户确认 -> Block`

优点：

- 减少 Token 成本
- 减少延迟
- 减少隐私暴露
- 避免 API 不可用时产品失效

## 今日战报为什么重要

它同时承担三个作用：

1. 用户价值证明：今天到底替你送走了多少垃圾号。
2. 情绪价值：让枯燥统计变成梗。
3. 产品传播：卡片天然适合发到 X。

这不是一个附属功能，应当进入早期 Roadmap。
