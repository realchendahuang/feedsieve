# 打野（排位赛）产品方案

> 状态：规划中（2026-09-11）。已有基础：服务端计分 / 赛季 / 榜单页 / 邮箱绑定已上线（commit 654d9b5 起），本文档定义在其上的产品化改造。

## 1. 定位

打野是 FeedSieve 的游戏化成长体系：用户用子弹清理信息流的黄推与垃圾账号，获得战报、排名与称号，最终在社区里混个脸熟——这是榜单的社交价值所在。

计分口径沿用已拍板方案（按共识击杀，而非拉黑数量，防误拉黑激励）：

- 开火 = 拉黑上报；确认击杀 = 账号收敛为共识黑名单成员且当前仍投 blocked 票 → +1
- 首杀 = 该账号最早的上报者且落在同一赛季 → +1
- 误伤 = 票项被翻案或进维护者白名单 → −2
- 周赛季（ISO 周），结算 Top 3 且命中率 ≥80%、开火 ≥10 发 → 永久称号「猎黄人」

## 2. 命名体系

| 词汇 | 指代 |
| --- | --- |
| 打野 | 玩法总称，一级入口名（tab 名） |
| 战报 | 个人数据卡片（击杀 / 命中率 / 子弹 / 百分位） |
| 子弹 | 日拉黑配额（沿用现名） |
| 榜单 | 周榜网页 |
| 猎黄人 | 赛季结算称号（保留） |
| 称号 | 累计击杀自动晋升的头衔（滤福系 / 鞭福系） |
| 葫芦娃 | 总榜名次徽标：大娃→七娃（1-7 名）、小金刚（8-50） |

## 3. 改造一：弹窗「打野」一级 tab

弹窗底部菜单新增「打野」，与名单 / 关键词 / 设置并列。现有 HunterBar 与 HunterProfile 从名单页整体迁入，名单页回归纯名单。

Tab 内结构：

1. **战报**（个人卡片）
   - 本周排名 + 确认击杀 + 命中率 + 子弹余量
   - 新增百分位展示：「打败了 N% 的猎手」（排名 / 榜单总人数，前端换算）
   - 称号徽章：按累计击杀晋升的称号（见 §6），百分位与称号并存展示
   - 未上榜入口态：显示「本周零杀」引导，保证任何用户都有从弹窗到榜单的路
2. **榜单速览**：Top 10 直接读 `POST /v1/leaderboard`（公开端点，无需凭证）
   - 我的行永远显示（置底），上榜则高亮
3. **完整榜单 →**：跳官网 `/leaderboard`，带 `?me=<加盐哈希前12位>` 高亮标识（页面加载即从地址栏抹除，现有行为不变）

界面遵循弹窗约定：只放标题、数据、控件；状态反馈瞬时自动消失，不遮挡。

## 4. 改造二：档案社交化（X handle）

把匿名猎手变成可认识的人：

- 档案新增 X handle 字段：`installations` 表加列，`/v1/player/profile` 的读写扩展该字段；格式校验（`^[a-zA-Z0-9_]{1,15}$`）即可，不改名归属
- 榜单行（网页 + 弹窗速览）渲染可点击的 `@handle`，直达 `x.com/<handle>`
- 取舍（拍板记录）：bio 与 X handle 均自报、不审核、不验证归属——不审就都要认；邮箱不公示

## 5. 榜单页与认领通道（2026-09-12 定稿）

网页 `/leaderboard` 纯观看：周榜/总榜切换 + me 高亮，不提供认领、登录与编辑。认领与编辑只在扩展弹窗做一次：邮箱验证码绑定 → 解锁昵称 / 简介 / X handle，此后免登录（安装 ID 即凭证）。

- 不做网页认领 / page token：浏览器拿不到安装 ID，曾设想的「凭邮箱验证码换编辑 token」双通道已撤——两处认领用户分不清用途，且邮箱验证的本职已经由扩展绑定完成
- 服务端保留 `email_codes` / `bind-email` / `verify` / `/v1/player/profile`（安装 ID 凭证）通道不变
- 未装扩展的网页访客不下身份（不能贡献就没有档案），保持零步骤原则

## 6. 称号系统

按**累计确认击杀**（全部赛季合计，服务端派生）自动晋升，共 8 级，滤福系与鞭福系交替（鞭福 ≈ 蝙蝠侠谐音）：

| 累计击杀 | 称号 |
| --- | --- |
| 1 | 滤福娃 |
| 10 | 鞭福娃 |
| 100 | 滤福侠 |
| 500 | 鞭福侠 |
| 1000 | 滤福王 |
| 2000 | 鞭福王 |
| 5000 | 滤福王中王 |
| 10000 | 鞭福王中王 |

规则：

- 阶梯按数量级展开（1 → 1 万），王中王是绝大多数人永远够不着的 apex；上线后看玩家分布再调（改阈值是改数据，不是改逻辑）。
- 称号永久生效，只升不降（误伤扣分作用于分数与排名，不降称号）。
- 展示优先级：榜单行与战报显示当前称号；周结算称号「猎黄人」作为独立荣誉并存展示。
- 未上榜从未开火：无称号（不显示「滤福娃」，那需要第一杀来解锁）。
- 服务端实现：累计击杀全量聚合（同榜单口径、不设时间窗），`installations` 加称号派生列，随榜单 dirty 懒重算；阈值常量表放在 `LEADERBOARD` 同处。

## 7. 总排行榜（累计榜）

与周榜并存的总排行：按累计分数（击杀 + 首杀 − 误伤，口径同周榜、不设时间窗）排名，行内挂分段位徽标。徽标随排名流动，不是永久称号（排名波动大，永久化会掉价；永久荣誉只有称号阶梯 + 周结算两类）：

| 名次 | 徽标 |
| --- | --- |
| 1 | 大娃 |
| 2 | 二娃 |
| 3 | 三娃 |
| 4-7 | 四娃 / 五娃 / 六娃 / 七娃 |
| 8-50 | 小金刚 |

命名取自「福滤娃 ≈ 葫芦娃」的品牌谐音，前七名一人一娃、名次即角色，8-50 合体为小金刚。状元及第系 / 清宫爵位系已否决（政治隐喻不收）。周榜结算荣誉（猎黄人 / 榜一大哥 / 百步穿黄 / 出黄入化）照常发，两套互不可替代。

弹窗速览仍用周榜，总榜只在网页看；榜单页加「周榜 / 总榜」切换，同一接口加 `scope=all`。

## 8. 服务端改动清单

| 改动 | 位置 |
| --- | --- |
| `installations` 加 `x_handle` 列（迁移） | community-api migrations |
| `/v1/player/profile` 扩展 `x_handle` 读写与校验 | `src/player.ts` |
| 百分位与总人数字段加入 `/v1/leaderboard` 响应 | `src/leaderboard.ts`（缓存结构同步扩展） |
| `installations` 加 `title`→称号派生列 + 累计击杀聚合（称号晋升） | `src/leaderboard.ts` + migrations |
| `/v1/leaderboard` 加 `scope=all`（总榜聚合，口径同、无窗口） | `src/leaderboard.ts` |

扩展现有不变量：安装 ID 加盐哈希即凭证；公开面只暴露哈希前缀；`POST` 传 ID，不进 URL。

## 9. 里程碑

1. **M1 打野 tab**：弹窗一级入口、战报（百分位）、Top 10 速览、 HunterBar/HunterProfile 迁移 —— 纯扩展侧，见效最快
2. **M2 X handle + 称号**：迁移 + profile 扩展 + 榜单行渲染 + 称号晋升（累计击杀阶梯） —— 一个小迭代可随 M1 同发
3. **M3 网页纯观看收尾**：榜单页周榜/总榜与 me 高亮（无 me 走 GET 边缘缓存）；认领/编辑通道只在扩展弹窗，不重复做页面内认领

每个里程碑独立可发布；发布节奏由用户逐次点头。

## 10. 非目标与红线

- 弹窗不内嵌完整榜单（链接出去）
- 不引入账号密码 / 会话登录体系；身份 = 安装 ID 哈希 + 邮箱验证码认领
- 不做 bio / handle 审核；不公示邮箱
- 推文原文永不出设备（红线不变）；计分只由服务端从共识数据派生，客户端报数不作数
- 段位是展示层包装，不进服务端计分逻辑
