## Unreleased — 人工判断优先与个人保护

- **漏网账号入口**：每条未标注推文和 popup 都可直接「标记垃圾并拉黑」；用户不用先理解检测规则或举报协议。
- **关注保护**：完整同步用户自己的 X 关注列表，作为仅本地、每用户独立的保护名单；同步失败不覆盖旧版本，也不上传社区。
- **识别收紧**：关键词、默认昵称和本地复读等单信号退出用户自动标注层；相似内容与可疑域名只在彻底档提示复核，且不进入批量动作。
- **理由改写**：主界面使用“3 人标记为诈骗”“与已确认垃圾账号内容高度相似”等普通表述，去掉模板、指纹、ruleId 等技术黑话。
- **社区清理队列**：只处理 strong、至少 3 个独立标记且无抢救票的条目；自动排除关注、个人白名单和已拉黑账号，支持持久进度、暂停、继续、取消。
- **防止票数自激**：社区清理产生的拉黑只做本地动作记录，不再次上传为新的举报票。

## v0.7.1 — 误标治理与菜单重做（2026-09-01）

### 菜单与交互

- **420×600 工作区**：popup 从 280px 窄长菜单升级为更易读的固定工作区，使用 Chrome action popup 允许范围内的高度，不再靠不断向下堆卡片扩展功能。
- **三页信息架构**：借鉴成熟扩展的分层方式，将高频清理、拉黑/误标名单、检测设置拆成底部三页导航；首页只保留当前页面待确认账号和唯一主操作。
- **每块只留一个标题**：删除品牌副标题、卡片眉题、设置项说明行、推荐尾标和底部安全文案；状态改成数字徽标或操作结果，不再用“大标题下面再解释一次”的堆字方式。
- **误标记录可读**：“误标白名单”独立成页，直接显示账号、加入日期、命中来源、规则 ID 和当时的检测理由，便于按规则复盘，而不是只看到 handle。
- **检测强度单行控制**：三档选择只显示“清爽 / 标准 / 彻底”，具体证据范围收进悬停提示，不占菜单正文。
- **渐进披露战报**：今日统计保留在首页次级卡片，分类图、生成卡片和分享到 X 默认收起，减少首屏文案和操作竞争。
- **双语与无障碍细化**：中英文切换移入设置页；导航、列表页签、开关、刷新和详情均补齐语义标签、键盘焦点与减少动画支持。
- **可重复视觉检查**：新增 `pnpm --filter @feedsieve/extension preview:popup`，用真实 React popup、浏览器 API 模拟数据和三种视图 query 做截图与交互回归。

### 修复

- **数字账号误标收紧**：X 懒加载或引用帖暂时读不到昵称时，不再仅凭“字母 + 长数字” handle 判为垃圾；只有昵称本身也明确是 `User12345` / `用户 12345` 这类默认数字名时才命中。
- **引用帖证据隔离**：Reader 不再把嵌套引用帖的正文和外链算到引用者头上，避免“评论/引用垃圾内容的正常账号”被当成原作者。
- **复读必须跨账号**：大扫除档的本地复读从“出现 3 次”改为“至少 3 个不同 handle 使用同一指纹”；同账号重复发帖或 X 虚拟滚动重挂 DOM 不再累计误标。
- **“误标？”不再只有本地效果**：仍然立即加入个人白名单，同时在社区贡献开关开启时显式上报检测来源、规则 ID 和当时的可读理由；网络失败不影响本地白名单的一票否决。
- **本地证据可追溯**：新加入白名单的条目保存 `detectionSource` / `ruleId` / `detectionReason`，旧版白名单记录保持兼容。
- **后台误标审计**：新增 `/admin/false-positives` 和 `admin.sh false-positives`，按规则汇总并返回最近 200 条反馈；不返回安装标识，不存推文原文。
- **未知账号也算反馈成功**：本地启发式误标的账号即使尚未进入社区 accounts 表，纠错证据仍会留在 rescues 表，不再向用户显示成失败。
- **历史黑白名单补传**：升级、浏览器启动和重新开启“名单上传”时，会分批同步本机已有黑名单与白名单；旧黑名单缺少分类时按 `other` 上传，旧白名单仍可只传 handle。
- **当前判断唯一计票**：新增 `active_labels`，每个匿名安装对每个账号只能保留“拉黑 / 白名单”中的一个当前标签；后一次改判覆盖前一次，原始 reports / rescues 证据仍留作审计。
- **删除名单即撤票**：本地撤销拉黑或移出白名单后调用 `/v1/labels/retract` 撤回当前票，不让过期判断继续污染评分。
- **白名单也带账号 ID**：有本地缓存时同时上传可选 `x_user_id`，账号改名后仍可归并；无 ID 不阻塞负样本上传。
- **异常响应不再卡加载**：当前页面消息收到非数组结果时按空清单降级，避免内容脚本冷启动或旧消息形状让 popup 永久停在“读取中”。

v0.4 目标：**换号再快，话术和域名认得出来。**

### 能力清单

- **内容指纹（Content Fingerprint）**：归一化话术文案的单向哈希，≥2 个独立安装上报同一指纹才下发；扩展在「大扫除」档用它标注换号复读同一模板的账号（`source=fingerprint · 社区指纹`）。
- **外链域名（Domain Reputation）**：垃圾外链 hostname 随上报入库，门槛同指纹；「大扫除」档按域名标注（`source=domain`）。
- **本地复读追踪**：同一模板文本在会话内出现 ≥3 次 → 黄框，纯内存、不持久不上传。
- **已拉黑回显**：已拉黑账号仍被 X 返回时如实标注（`已拉黑账号 · X 仍展示` + 移除推文按钮）。
- **v0.3 全量入库**：报备信任 + 突发检测、抢救票、改名别名、策略透明（/v1/policy + manifest 内嵌 + yaml drift guard）一并上线。
- **UI 整理**：设计令牌统一（popup + 徽章两处黄色系收敛为同一套变量）；徽章按钮分组（主操作 vs 抢救/误标？）；popup 强度档悬停解释；删死代码。
- **种子名单**：6 个人工背书种子（strong）入 D1，快照 v2026.08.30.1 发布并镜像回仓库（git diff 即审计日志）。

### 安全边界

- 指纹是归一化话术的单向哈希，原文永不出设备；link_domains 仅 hostname；绝无浏览数据。
- 指纹/域名证据只在「大扫除」档参与标注；标准/清爽档保持名单 + 启发式行为不变。

## v0.1.0 — 能真正拉黑（2026-08-27）

v0.1 目标：**没有后端、没有 AI，也能真正送走垃圾账号。**
成功标准：安装后 5 分钟内能把第一批垃圾账号真正拉黑，手机端同步清净，断网仍然能标注。

### 能力清单

- **黄框标注（带理由）**：内置名单 + 启发式（giveaway/空投模板、中文色诱话术、数字名账号、可疑链接域名），每条标注可解释来源与规则。
- **顺手拉黑**：时间线黄框徽章上单账号直拉黑，经 X 网页端原生产链路（`1.1/blocks/create.json`，页面登录会话），rest_id 缓存 miss 时按 handle 当场解析回填。
- **拉黑即消失**：拉黑确认成功后，该账号页面上可见的推文一并移除（对齐 X 原生拉黑行为）。
- **待拉黑列表**：popup 可看、可单项移除、可清空；勾选在时间线黄框里进行。
- **一键批量拉黑**：popup 一键执行整张待拉黑列表，逐条率控、失败保留并显示原因（限流/登录失效/网络错误等）。
- **一键撤销**：已拉黑记录可单项或全部撤销（`1.1/blocks/destroy.json`），误伤可恢复。
- **本地统计**：标注 / 拉黑 / 撤销计数器，全部本地累计，不上报。
- **X DOM fixtures**：脱敏样本（timeline / search f=live / replies / profile）锁定 reader→detector 契约。

### 工程

- WXT 0.21 + React 19 + MV3，最小权限（storage + x.com）。
- 四包 monorepo：detector（纯逻辑）/ x-adapter / block-queue / extension。
- 95 个单元测试 + 本地质量门禁（lint / typecheck / test / build，pre-push 自动执行）。
- 架构借鉴 PureTwitter / TBWL 实证方案：XHR 桥（MAIN world）取 GraphQL 数据 → 原生 Block API 执行，不做任何 Hide / Collapse。

### 已知限制

- 已拉黑账号的推文在 X f=live 搜索流中重开页面仍可能被服务端返回（扩展在拉黑当次移除 DOM）；持久过滤已拉黑账号留待后续版本。
- 批量操作依赖当前活动标签页为 x.com 新版页面；多标签场景下旧标签可能提示找不到会话。
